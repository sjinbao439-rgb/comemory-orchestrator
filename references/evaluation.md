# 验证规范

验证分为数值与结构检查、语义案例审阅、服务联调三层。每层记录输入、处理结果和检查结论。

## 数值与结构检查

在技能目录运行：

```powershell
node --test scripts/timing.test.cjs scripts/validate.test.cjs scripts/jobs.test.cjs
node scripts/timing.cjs examples/timing.input.json
node scripts/timing.cjs examples/short-timing.input.json
node scripts/validate.cjs examples/jiangnan.input.json examples/jiangnan.plan.json
node scripts/jobs.cjs tasks examples/jobs.input.json
node scripts/jobs.cjs close examples/close.input.json
```

检查时间并集、短句时长、文字估算、时长守恒、来源引用、版本递增、片段依赖、迟到结果、失败和超时收束。任务脚本输出任务说明，由执行端提交；媒体校验标记由解码验证环节设置。

## 语义案例审阅

案例输入与输出位于 `evals/`。加载技能后独立生成计划，再执行结构检查和逐条语义审阅。评审条件单独保存，生成阶段只读取案例输入。

| 案例 | 应有处理 |
|---|---|
| 动作句未结束 | “放学以后都会去……”进入缓冲，目的地随后文补齐 |
| 停顿与追问 | “我骑车……去上学”保持同一事件；下雨问句作为上下文；年代保留原话语气，画面年龄按回忆依据处理 |
| 补充纠正 | 石桥改为木桥，保持场景编号并递增版本；旧任务标记过时，更新相关事实与提示词 |

## 服务联调验收

使用一段包含自然停顿、追问和纠正的双人录音，完整运行转写、分镜、首帧、视频和归档。保存输入音频索引、确认转写、模型原始输出、计划版本、任务日志和媒体校验记录。

| 检查项 | 检查方式 |
|---|---|
| 转写与角色 | 对照原录音核对人名、年代、角色及音频区间 |
| 事实与分镜 | 逐条匹配原话，核对指代、否定、事件边界及新增内容 |
| 节奏 | 比较原话计时区间与展示总时长，记录差值 |
| 动态与连续性 | 检查主体运动、人物和物件特征、前后动作及参考帧承接 |
| 增量响应 | 记录原话确认至首帧、视频就绪的延迟及队列积压 |
| 修订与收束 | 检查旧版本拦截、失败终态、播放结束及保存回执 |
| 对话流畅度 | 记录系统追问、强制确认和中断次数及触发原因 |

## 补充回归场景

- 两位同类人物同时出现：保留指代并随上下文定位。
- “不是下雨，那是风”：排除雨景，表现风的环境运动。
- “后来才买自行车，以前走着去”：按事件顺序区分步行和骑车。
- 临时转写反复修订：原位更新，确认后提交一次。
- 照片与口述冲突：分别记录对应对象和适用范围。
- 服务中断或生成超时：保留原话和成功素材，任务进入终态。
- 连续长事件：逐片推进动作，核对末帧依赖和总时长。
